# v2.0.4 acceptance record

Release repository: https://github.com/D4gkan/Steam-Desktop-Authenticator-2.0

## Scope

The credential cleanup (`a8c8291`) and synthetic fixture (`6b49382`) change
ignore rules and test data only. Desktop runtime source is unchanged from
v2.0.3 before the release version label update. Android runtime differences
since v2.0.3 are the launcher icon fixes and the `AccountCard` Compose
annotation. Upstream secret-scanning CI is included from `b50fbce`.

Three Sol scouts at low reasoning effort reviewed desktop storage, Android
import/test boundaries, and release packaging. The release owner independently
checked their findings against source and Git diffs.

Version metadata commit: `c7d538e`.

## Compatibility

Desktop `Manifest.GetManifest` creates an empty manifest when no `maFiles`
directory exists. `SaveAccount` and `Save` create runtime storage as needed.
Android creates `maFiles` in the application's private files directory.
Neither client needs checked-in account records. The new fixture is in the
Android JVM test source set, outside production assets. Account serialization,
encryption, authentication and confirmation logic are unchanged by cleanup.

## Verification

- `.NET SDK 8.0.424`: `dotnet build SteamDesktopAuthenticator.sln -c Release -p:Version=2.0.4` passed with zero warnings and errors.
- An isolated desktop harness passed 12 checks: fresh manifest creation,
  loading the Android synthetic fixture, deterministic Steam Guard code
  generation against an independent Python HMAC calculation, plaintext
  save/reload, enabling encryption, locked loading without a passkey,
  encrypted reload, wrong-passkey rejection, removing encryption, preserved
  decrypted account data, and account deletion persistence. No Steam network
  requests were made.
- Launching the Release desktop application in an isolated writable directory
  created a clean manifest and stayed running without crash output. Visual
  inspection was blocked by missing macOS computer-use permissions.
- Source inventory and ignore-rule checks passed: no tracked maFile, maFiles,
  desktop bin or obj paths; account-file and runtime-manifest paths are ignored.

- Self-contained single-file Windows x64 and Linux x64 publishes passed with
  `dotnet publish src/App/App.csproj -c Release -r <rid> --self-contained
  -p:PublishSingleFile=true -p:Version=2.0.4`. Archives include all publish
  output, passed ZIP integrity checks, retain Linux executable permissions,
  and contain no account files, fixtures or signing keys.
- Android JVM tests passed in debug and release: three tests per variant,
  zero failures/errors, including the synthetic desktop-format fixture.
- Android lint **failed** with one pre-existing error and 15 warnings.
  `UnusedMaterial3ScaffoldPaddingParameter` at `SdaNavGraph.kt:95` predates
  the cleanup (introduced by `5ba4e84`, v2.0.2): `NavHost` ignores the outer
  scaffold padding, so content can overlap the bottom navigation bar. This
  release does not change that layout. No lint suppression or baseline was
  added. Kotlin analysis API warnings were also emitted by the lint tooling.

- Android debug and signed release APK builds passed, including the release
  vital-lint gate. The broader lint command still fails as described above.
  Build command from `Application/`:
  `JAVA_HOME=<JDK17> ANDROID_HOME=<SDK> bash ./gradlew
  -Dorg.gradle.java.home=<JDK17> test assembleDebug assembleRelease`.
  The explicit Java override avoids the existing Windows-specific Gradle
  setting; `bash` runs the wrapper, which is not executable in this checkout.
- APK signature verification passed and its certificate matches the existing
  keystore; package metadata is `com.sda.mobile`, version `2.0.4`, code `4`.
  APK integrity and exclusion checks passed for account records, test fixture
  markers and signing material. SHA-256 checksums cover all three binaries.

## Limitations

Verification uses synthetic account data; no live Steam login, linking,
revocation, trade approval or session refresh is exercised. Removing files from
Git does not establish that exposed Steam credentials were revoked.

The Android signing key and its configuration remain committed, as recorded in
finding 2 of the [security review](../security/codex-security-review-2026-09-03.md).
Signing identity remediation requires maintainer coordination. This release
does not claim to resolve that separate finding or the other findings in that
review. GitHub-generated source archives include tracked source files,
including the existing signing key.

Windows/Linux binaries were cross-published on macOS; they were not launched
on those operating systems. Android was built and JVM-tested without a
device/emulator UI test.
